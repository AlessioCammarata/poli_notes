What is a stream?
A **sequence** of elements from a **source** that supports data processing **operations**.
- Operations are defined by means of behavioral parameterization (**functional interfaces**)
Basic features:
- **pipelining**
- **Internal iteration**
	- no explicit loops statements
- **Lazy evaluation** (pull)
	- no work until a terminal operation is invoked

```java
Stream.of("All","along",..) // Source
.sorted() // Intermediate
...
.limit(4) // intermediate
.forEach(IO::println); // Terminal
```

##### Source generation in Stream
**generate()** -> Supplier\<T> s 
- Elements are generated by calling get() method of the supplier 
**iterate()** -> T seed, UnaryOperator\<T> f 
- Starts with the seed and computes next element by applying operator to previous element 
**empty()** 
- Returns an empty stream

	()->{

##### Flat mapping
Context:
- Stream elements are containers (e.g. List) -> Or elements are mapped to containers 
Problem: 
- Processing should be applied to all elements inside those containers 
Solution: 
- Use the flatMap() method

	\<R> Stream\<R>
flatMap(Function<T, Stream\<R>> mapper)
- Extracts a stream from each incoming stream element 
- Concatenate together the resulting streams
>Very common at the exam

```java
//Flatmapping
//We want to find the unique hobbies people are doing
//Person -> name, age, list of hobbies
// exist a getHobbies that return the list of hobbies
List<Person> persons = new LinkedList<Person>();
persons.add(new Person("Maria", 78, Arrays.asList("Horse riding","Netflix watching")))
persons.add(new Person("Umberto", 56, Arrays.asList("Volleyball")))
persons.add(new Person("Mia", 21, Arrays.asList("Martial arts","Netflix watching")))

// flatmap here is Converting the List of string into a stream of strings
persons.stream()
	.map(Person::getHobbies) // return a stream of list (of Hobbies)
	.flatMap(Collection::stream) // return a stream of strings
	.distinct()
	.forEach(IO::println);

// Horse riding, Netflix watching, Volleyball, Martial arts
```

#### Terminal Operations
**findAny**() Optional\<T>
- Returns the first element (order **does not** count) 
**findFirst()** Optional\<T>
- Returns the first element (order counts) 
**min()/ max()** Optional\<T>
- Finds the min/max element based on the comparator argument
**count()** long 
- Returns the number of elements in the stream 
**forEach()** void 
- Applies the Consumer function to all elements in the stream
**anyMatch()** boolean 
- Checks if any element in the stream matches the predicate 
**allMatch()** boolean 
- Checks if all the elements in the stream match the predicate 
**noneMatch()** boolean 
- Checks if none element in the stream match the predicate

>The first cases return Optional because if the stream is empty you can't say which is the maximum or the first element since it doesn't exist

##### Other Terminal Operations
**Stateless operations** 
- No internal storage is required – E.g. map, filter 
**Stateful operations** 
- Require internal storage, can be 
	- **Bounded**: require a fixed amount of memory – E.g. reduce, limit 
	- **Unbounded**: require unlimited memory – E.g. sorted, collect

**Operations**:
- reduce()
- collect()
###### Reduce
**reduce()** T, BinaryOperator\<T> 
- Reduces the elements using an identity value and an associative merge operator 
>To compute the maximum in positive numbers the identity value is 0.
>In multiplication is number 1.
>
>It also need an associative merge operator: starting from the result it aggregate the results
>- The full stream collpase into a single value, for example the max.
###### Parallel streams
You can parallelize the stream, in each of the partition of the streams you can apply the reduction, so it is faster.
```java
IntStream.of(numbers) 
		.parallel() //up to n times faster (n = number of CPU cores)
		.reduce(0, Math::max); 
```
>More efficient if we have large sources.

###### Collect
**collect()** Collector<T,A,R> 
- Reduces the stream to create a collection such as a List, a Map, or even an Integer.

Stream.collect() takes as argument a recipe for accumulating the elements of a stream into a summary result.
- It is a **stateful** operation
```java
class Acc { int n; } 
int s = Stream.of(numbers). 
			collect(Acc::new,           // supplier 
					(a,i) -> a.n+=i,    // accumulator 
					(a1,a2)->a1.n+=a2.n // combiner 
				).n;
```
>Combiner is used when you have parallelized stream, so that you can combine the result of different streams (parallel streams).

It's useful if we need to collect in a more complex (box superiore tipo) structure, for instance:
```java
List n = Stream.of(numbers). 
			collect(LinkedList::new, // supplier 
					List::add,       // accumulator 
					List::addAll);   // combiner
```
>This way you obtain a List of numbers

This also support the **Lazy Evaluation**.
Examples:
```java
//We want to collect into a List
List<Integer> numbers = new LinkedList<Integer>();
nummbers.add(1);
nummbers.add(3);
nummbers.add(2);
nummbers.add(8);

List<Integer> oodNumbers = numbers.stream()
								.filter(x->x%2!=0) // just odd numbers
								.collect(LinkeList::new

										List::addAll
									);
oddNumbers.forEach(IO::println); //FOREACH of collections not of streams
// 1
// 3

// (1,3) -> LinkedList of 2 elements
```

>You can also use a collector:
```java
List<Integer> oodNumbers = numbers.stream()
								.filter(x->x%2!=0) // just odd numbers
								.collect(Collectors.toList());
// (1,3) -> LinkedList of 2 elements
```
