***Sequential process:***
- Actions are executed one **after** the other
- **Deterministic behaviour**
	-In teoria lanciandolo in momenti diversi ottieni lo stesso risultato.
	Non dipende da:
	- Time of execution
	- Speed of execution
	- Number of active processes on the same system

***Concurrent process execution:***
- More than one action can be executed at the **same** time
	- There is not order relation 
	- Non deterministic behavior 
- **Real concurrency** 
	- on multi-processor or multicore systems 
- **Pseudo-concurrency** 
	- on mono-processor systems

Several processes are started at bootstrap, these are called **Automatic** (like daemon) if they are started at bootstrap and terminated at shut-down.
Other processes are started at bootstrap only **On user request**.

#### Process Identity and Process Control
 Every process has a unique identifier 
 - **PID** or Process Identifier 
 
 The PID is a **non negative integer** 
 -  Although a PID is **unique**, UNIX reuses the numbers of terminated processes. 
 - PID can be used by concurrent processes for creating unique objects, or temporary filenames 
	 - For example : "sprintf(filename, "file-%d" getpid());" creates a different process-dependent filename

```c
int main(){
	printf("PID: %d\n", getpid());
	
	return 0;
}
```

Some identifiers are **reserved** 
- The first process, PID=0, is a **system process** 
	- The **swapper**, which is responsible for memory management and process scheduling 
	- Executed at the kernel level 
- The second process, PID=1, is **init** a daemon 
	- invoked at the end of the bootstrap 
	- executed at user level 
	- with super-user privileges 
	- Becomes the parent of each orphan process, i.e., of a child of a parent process already terminated
```c
#include <unistd.h>

pid_t getpid();
pid_t getppid(); //Parent process ID
```

#### Process creation
To create a processs exists more system calls, in linux fork() while in windows **CreateProcess**():
##### Fork()
System call used to create new processes.
The child is a copy of the parent exlcudinte the PID returned by fork
```c
#include <unistd.h>

pid_t fork(void);
```
returned values:
- If fork returns without error
	- child PID in the parent process
	- Zero in the child process
- Fork return -1 in case of error
```c
#include <unistd.h>
... 
pid_t pid; 
... 
pid = fork(); 
switch (pid) { 
	case -1: 
		// Fork failure 
		... 
		exit (1); 
	case 0: 
		// Child 
		... 
	default: 
		// Parent 
		... 
} 
...
```
>So when you start a fork the child is initialized with the parent code starting from the fork() function.

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main() {
    printf("B PID: %d PPID %d\n", getpid(), getppid());
    
    fork();
    // Two processes
    printf("A PID: %d PPID %d\n", getpid(), getppid());
    printf("done\n");

    return 0;
}
```
Parent and child share their code, but they have a different **PCB**. (Process Control Block)
```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main() {
    int r; //pid_t r;

    printf("B PID: %d PPID %d\n", getpid(), getppid());
    
    r = fork(); // 0 in the child, PID of child in parent code
    // Two processes
    if (r==0) {
        printf("CHILD PID: %d PPID %d R: %d\n", getpid(), getppid(), r);
    } else if (r>0) {
        printf("PARENT PID: %d PPID %d R: %d\n", getpid(), getppid(), r);
    }
    printf("done\n"); // executed by both

    return 0;
}
```

They also share the **value of the data at the time of fork**, Parent and child may then change the data values independently.
```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main() {
    int r, a=3; //pid_t r;
    printf("B PID: %d PPID %d\n", getpid(), getppid());
    
    r = fork();
    // Two processes
    if (r==0) {
        printf("CHILD PID: %d PPID %d R: %d\n", getpid(), getppid(), r);
        printf("CHILD done A: %d\n", a);
    } else if (r>0) {
        a = 5;
        printf("PARENT PID: %d PPID %d R: %d\n", getpid(), getppid(), r);
        printf("PARENT done A: %d\n", a);
    }
    printf("done\n");

	// 5 in parent
	// 3 in child
    return 0;
}
```

#### Wait() and Waitpid
When a process terminates (normally or not)
- The kernel sends a signal (**SIGCHLD**) to its parent 
- For the parent this is an asynchronous event 
- The parent process may 
	- Manage the child termination (and/or the signal) 
		- **Asynchronously** 
		- **Synchronously** 
	- **Ignore** the event (**default**)

A parent process can manage child termination
- Asynchronously: using a signal handler for signal **SIGCHLD**
- Synchronously: by means of system calls
	- **wait** 
	- **waitpid** 
>Example:
```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/wait.h>

void f1() {
    sleep(4);
    printf("f1()\n");
}
void f2() {
    sleep(1);
    printf("f2()\n");
}
void f3() {
    sleep(1);
    printf("f3()\n");
}

int main() {
    if (fork()) {
        //Parent
        f1();
        wait(0); // Blocked until one of his child has finished
        f3();
    }else{
        // CHILD
        f2();
        exit(0);
    }
    return 0;
}
```
>Execution of f1 and f2 in parallel, f3 after both finished. -> total 5 seconds
###### Wait()
 ```c
 #include <sys/wait.h> 
 
 pid_t wait (int *statLoc);
 ```
 A call of the system call **wait** by means of a process 
 - **Returns an error** if the calling process **has not children**:
	 - A process without children is not supposed to do a wait 
	 - In this case the returned value is -1
 - Blocks the calling process if **all its children are running** (none is already terminated) 
	 - wait will return as soon as one of its children terminates
- Returns to the process (immediately) the termination status of a child, if at least one of the children has ended (and it is waiting for his termination status to be recovered) 
	- When a process ends and the parent does not do a wait, its termination status remains pending 
	- Some resources associated with the process remain blocked

>The **statLoc** parameter is an **integer pointer**. Which can be obtainerd using macros (WIFEXITED, WIFSIGNALED).
>
>**Example**:
```c
 /*
 *  Illustrates fork, wait and exit return information
 *  Once run: Use 
 *  echo $?
 *  to make the shell print-out the parent return value (25)
 */

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main ()
{
  pid_t pid, cpid;
  int status;

  fprintf (stdout, "Starting Process: PID=%d\n",  getpid());

  pid = fork();

  if (pid != 0) {
    // Parent
    fprintf (stdout, "Parent: PID=%d; FatherPID=%d; ReturnPID=%d\n",
             getpid(), getppid(), pid);

    sleep (5);
    // 6 1011100
    printf("PARENT blocked on wait()\n");
    cpid = wait (&status);
    fprintf (stdout, "Parent Wait: ChildPID=%d Status=%x ", 
             cpid, status); // cPID and status
    fprintf (stdout, "WIFEXITED=%d WEXITSTATUS=%d\n",
             WIFEXITED(status), WEXITSTATUS (status)); // 1, 6
    printf("Parent complete\n");
    exit (25);
  } else {
    // Child
    fprintf (stdout, "Child : PID=%d; FatherPID=%d; ReturnPID=%d\n",
             getpid(), getppid(), pid);
    sleep (10);
    fprintf (stdout, "Child complete\n");
  
    exit (6);
  }
}
```
If a child has perform an exit but the parent is still running, the child become a **zombie**.
In a **zombie state** some resources are not released for other processes.
When the parent terminates than the zombie resources are also released.

>An **orphan process** cannot be a zombie. (systemd or Init automatically performs wait when the child finish).
###### Waitpid()
To use wait for a specific child, you need to 
- Control the PID of the terminated child 
- Possibly store the PID of the terminated child in the list of terminated child processes (for future checks/searches) 
- Make another wait until the desired child is terminated 

If a parent needs to wait a specific child it is better to use **waitpid**, which 
- suspends execution of the calling process until a child, specified by pid argument, has changed state 
- **waitpid**() has a not blocking form (not default)
```c
#include <sys/wait.h> 

pid_t waitpid ( 
	pid_t pid, 
	int *statLoc, 
	int options);
```
The parameter **pid** allows waiting for 
- Any child (waitpid\==wait) (pid = -1) 
- The child whose PID=pid (pid > 0) 

The **options** parameter allow additional controls 
- Default is 0, or is a bitwise OR of constants 
	- **WNOHANG**, if the child specified by PID is running, the caller does not block (**not blocking version of wait**) 
	- WCONTINUED and WUNTRACED allow to know the status of a child in particular conditions

>Not all the graphs could be implemented, (child cannot wait for fathers mainly, Also between 2 different children)
